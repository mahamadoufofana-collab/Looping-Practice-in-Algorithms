Problem 1

Counting Sequence

Display integers from 1 up to N using a forward counting loop.

Output: 
Click "Run Algorithm" to see the output.
How It Works (Explanation & Pseudocode)

Objective: Generate and print numbers starting from 1 up to N.

Steps:

  1. Read input n and ensure it is $\ge 1$.
  2. Start a counter variable i = 1.
  3. In each step, append i to our result list.
  4. Increase i by 1 until i exceeds n.

Pseudocode:

SET result = ""
FOR i FROM 1 TO n DO
    APPEND i TO result
ENDFOR
DISPLAY result

Variables: n is the target number, i is the loop counter.

Time Complexity: $O(N)$ — repeats $N$ times.

Countdown

How It Works (Explanation & Pseudocode)

Objective: Count backward from N to 1 and finish with a launch word "Start!".

Steps:

  1. Start loop counter i at n.
  2. Continue as long as i >= 1.
  3. In each turn, record i and decrement i by 1 (i--).
  4. After loop ends, add "Start!".

Pseudocode:

SET result = ""
FOR i FROM n DOWNTO 1 DO
    APPEND i TO result
ENDFOR
APPEND "Start!" TO result
DISPLAY result

Variables: n is the starting count, i counts downward.

Time Complexity: $O(N)$.

Problem 7

Count and Sum of Digits

Calculate the number of digits and their sum without converting to a string.

Output: 
Click "Run Algorithm" to see the output.
How It Works (Explanation, Pseudocode & Trace Table)

Objective: Extract digits purely using arithmetic (modulo % 10 and division / 10).

Special Case for N = 0: Zero has 1 digit and digit sum = 0.

Algorithm Steps:

  1. Take absolute value of N in a temporary variable temp.
  2. While temp > 0:
    • Extract last digit: digit = temp % 10.
    • Add to sum: sum = sum + digit.
    • Increment count: count = count + 1.
    • Remove last digit: temp = Math.floor(temp / 10).

Pseudocode:

SET count = 0, sum = 0, temp = ABS(n)
IF temp == 0 THEN
    count = 1
    sum = 0
ELSE
    WHILE temp > 0 DO
        digit = temp MOD 10
        sum = sum + digit
        count = count + 1
        temp = FLOOR(temp / 10)
    ENDWHILE
ENDIF
DISPLAY count, sum

Problem 8

Prime Number Checker

Check if N is prime by testing divisors only up to √N.

Output: 
Click "Run Algorithm" to see the output.
How It Works (Explanation & Pseudocode)

Objective: Determine whether N has any factors other than 1 and itself.

Rules:

  • Numbers less than 2 ($N < 2$) are not prime.
  • Check divisors i from 2 up to $\sqrt{N}$ (or i * i <= n).
  • If any i divides n with remainder 0, then n is composite.
  • If no divisors divide n, then n is prime.

Pseudocode:

IF n < 2 THEN RETURN false
SET isPrime = true
FOR i FROM 2 WHILE i * i <= n DO
    IF n MOD i == 0 THEN
        isPrime = false
        BREAK
    ENDIF
ENDFOR
RETURN isPrime

Time Complexity: $O(\sqrt{N})$.

Problem 13

Find All Prime Numbers

Display all prime numbers from 2 through N using the square-root divisor method.

Output: 
Click "Run Algorithm" to see the output.
How It Works (Explanation & Pseudocode)

Objective: Iterate through every number from 2 to N, check if it is prime using divisors up to its square root, and collect all primes.

Steps:

  1. Outer loop iterates num from 2 up to n.
  2. For each num, inner loop checks divisors d from 2 up to d * d <= num.
  3. If no divisor divides num evenly, add num to our prime list.

Pseudocode:

SET primes = []
FOR num FROM 2 TO n DO
    SET isPrime = true
    FOR d FROM 2 WHILE d * d <= num DO
        IF num MOD d == 0 THEN
            isPrime = false
            BREAK
        ENDIF
    ENDFOR
    IF isPrime THEN APPEND num TO primes
ENDFOR
DISPLAY primes

Time Complexity: $O(N \sqrt{N})$ or $O(N^{1.5})$.

Problem 14

Pascal’s Triangle

Generate the first N rows using values from the previous row (not hard-coded).

Output: 
Click "Run Algorithm" to see the output.
How It Works (Explanation & Pseudocode)

Objective: Compute rows where each interior element is the sum of the two numbers directly above it from the previous row.

Rules:

  • First and last elements of each row are always 1.
  • For any intermediate element at column j in row i: row[j] = prevRow[j - 1] + prevRow[j].

Pseudocode:

SET triangle = []
FOR i FROM 0 TO n - 1 DO
    SET currentRow = []
    FOR j FROM 0 TO i DO
        IF j == 0 OR j == i THEN
            currentRow.APPEND(1)
        ELSE
            currentRow.APPEND(triangle[i-1][j-1] + triangle[i-1][j])
        ENDIF
    ENDFOR
    triangle.APPEND(currentRow)
ENDFOR
DISPLAY triangle

Time Complexity: $O(N^2)$ to fill $\frac{N(N+1)}{2}$ values.

Problem 16

Seating Arrangement Analysis

Analyze 3 rows of theater seats: O = empty, X = occupied. Count seats, calculate occupancy rate, and find row with most occupied seats with clear tie handling.

Format: Space-separated O and X characters on 3 rows.
Output: 
Click "Run Algorithm" to see the output.
How It Works (Explanation & Pseudocode)

Objective: Process a 2D grid matrix of seating records to calculate seat counts, percentage occupancy, and find the maximum occupied row.

Tie Handling Strategy:

When searching for the row with the most occupied seats, the algorithm tracks the maximum count found. If multiple rows share the highest occupied seat count, our algorithm does not arbitrarily pick one; instead, it detects all tied row numbers and displays them clearly (e.g. "Tie between Row 1 and Row 3 with 2 occupied seats each").

Pseudocode:

SET totalEmpty = 0, totalOccupied = 0
SET rowCounts = []

FOR each row r IN seatingGrid DO
    SET countX = 0, countO = 0
    FOR each seat IN row r DO
        IF seat == 'X' THEN countX++
        ELSE IF seat == 'O' THEN countO++
    ENDFOR
    rowCounts.APPEND(countX)
    totalOccupied += countX
    totalEmpty += countO
ENDFOR

SET percentage = (totalOccupied / (totalOccupied + totalEmpty)) * 100
FIND all rows in rowCounts with value equal to MAX(rowCounts)
DISPLAY statistics and tie-handled row results

Time Complexity: $O(R \times C)$ where $R$ is rows and $C$ is columns.

Question 1 • Problem 8

Why Checking Divisors Up to the Square Root (√N) Is Sufficient

When checking whether a positive integer $N$ is prime, we want to know if it has any positive divisors other than $1$ and $N$. A brute-force approach checks every integer from $2$ up to $N - 1$, which requires $O(N)$ operations. However, we only need to test divisors up to $\sqrt{N}$.

Mathematical Proof by Contradiction:

Suppose $N$ is a composite number. Then it can be factored as:

$$N = a \times b \quad \text{where } 1 < a \le b < N$$

Now, let us examine what happens if both factors $a$ and $b$ were strictly greater than $\sqrt{N}$:

$$\text{If } a > \sqrt{N} \quad \text{and} \quad b > \sqrt{N},$$

$$\text{then } a \times b > \sqrt{N} \times \sqrt{N} = N.$$

This yields $a \times b > N$, which is a direct mathematical contradiction because $a \times b$ must equal $N$.

Conclusion: In every factor pair $(a, b)$, at least one factor must be less than or equal to $\sqrt{N}$ ($a \le \sqrt{N}$). If no whole divisor divides $N$ evenly in the range $[2, \lfloor\sqrt{N}\rfloor]$, then no matching paired factor can possibly exist above $\sqrt{N}$. Therefore, $N$ is unconditionally prime!

Concrete Example with N = 37:

$\sqrt{37} \approx 6.08$. Divisors to test: 2, 3, 4, 5, 6.

  • $37 \div 2 = 18.5$ (No)
  • $37 \div 3 = 12.33$ (No)
  • $37 \div 4 = 9.25$ (No)
  • $37 \div 5 = 7.4$ (No)
  • $37 \div 6 = 6.16$ (No)

Because none of these 5 numbers divide 37, we stop immediately. We do not need to test 7, 8, 9, ... up to 36. Checking up to $\sqrt{N}$ saved over 30 unnecessary iterations!

Understanding how nested loops execute is fundamental to algorithmic analysis. Let us analyze Problem 12 with $N = 4$:

        product = i * j
    ENDFOR
ENDFOR

Total Inner Loop Iterations (Full Grid) = 4 + 4 + 4 + 4 = 16 iterations ($N^2$)

2. Relationship to the Triangular Formula $\frac{N(N + 1)}{2}$:

The assignment asks about the formula $\frac{N(N+1)}{2}$. In algorithmic multiplication, because multiplication is commutative ($i \times j = j \times i$), the $N \times N$ grid is symmetric across the diagonal.

If an algorithm only computes the unique symmetric pairs or a triangular half (such as in Right Triangle Problem 10 or unique pair searching where $j \le i$):

  • Row 1 calculates: 1 item ($j = 1$)
  • Row 2 calculates: 2 items ($j = 1, 2$)
  • Row 3 calculates: 3 items ($j = 1, 2, 3$)
  • Row 4 calculates: 4 items ($j = 1, 2, 3, 4$)

$$\text{Sum} = 1 + 2 + 3 + \dots + N = \sum_{k=1}^{N} k = \frac{N(N + 1)}{2}$$

For $N = 4$:

$$\frac{4(4 + 1)}{2} = \frac{4 \times 5}{2} = \frac{20}{2} = 10 \text{ iterations}$$

Summary: A full grid computes all $N^2 = 16$ cells, whereas the triangular / unique combination portion evaluates $\frac{N(N+1)}{2} = 10$ pairs.

Question 3 • Problems 13 & 15

Time Complexity Comparison: Problem 13 vs Problem 15

Both Problem 13 and Problem 15 employ nested loops, but their loop termination conditions differ significantly, resulting in different asymptotic behaviors:

Aspect Problem 13: Find All Primes up to N Problem 15: Target Sum Pairs in Array of Size M
Goal Find all primes from 2 to $N$ Find all pairs $(arr[i], arr[j])$ where $arr[i] + arr[j] = \text{target}$
Outer Loop Iterates num from 2 up to $N$ ($N - 1$ steps) Iterates index i from $0$ to $M - 1$ ($M$ steps)
Inner Loop Tests divisors d from 2 up to $\sqrt{\text{num}}$ Tests index j from $i + 1$ to $M - 1$ ($M - 1 - i$ steps)
Total Operations $\sum_{k=2}^{N} \sqrt{k} \approx \int_{2}^{N} x^{1/2} dx \approx \frac{2}{3} N^{1.5}$ $(M-1) + (M-2) + \dots + 1 = \frac{M(M - 1)}{2}$
Big-O Complexity $O(N \sqrt{N})$ or $O(N^{1.5})$ $O(M^2)$ quadratic time
Performance Growth For $N = 100$, operations $\approx 100 \times 10 = 1,000$ For $M = 100$, operations $\approx \frac{100 \times 99}{2} = 4,950$

Key Insight: Problem 13 is sub-quadratic ($O(N^{1.5})$) because the inner loop stops early at $\sqrt{num}$ rather than scanning all the way to $num$. In contrast, Problem 15 examines every combination of two items in the array, making its step count exactly quadratic ($O(M^2)$).
